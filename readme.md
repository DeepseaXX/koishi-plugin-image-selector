# 图片选择器

[![npm](https://img.shields.io/npm/v/@deepseaxx/koishi-plugin-image-selector?style=flat-square)](https://www.npmjs.com/package/@deepseaxx/koishi-plugin-image-selector)

把图片和视频按文件夹整理好，聊天时发送一个关键词，就能随机发出对应内容。也可以直接回复图片、视频或多层嵌套的合并转发聊天记录，把它们保存到图库。

## 先用起来

假设图片库目录里有一个文件夹：

```text
images/
└── 猫咪-猫图-喵星人/
    ├── 1.jpg
    └── 2.gif
```

发送下面任意一个词，插件都会从这个文件夹里随机发送文件：

```text
猫咪
猫图
喵星人 3
```

文件夹名称使用 `主关键词-别名1-别名2` 的格式。每一段都可以作为触发关键词。

## 常用指令

默认指令名称可以在设置中修改。

| 指令 | 用途 |
| --- | --- |
| `发图 关键词 [数量]` | 使用指令发出指定分类的随机图片或视频 |
| `存图 [关键词] [图片]` | 把图片或视频保存到指定分类 |
| `图库列表` | 查看当前图库中的分类和别名 |
| `刷新图库` | 文件夹有变化时，立即刷新缓存 |

### 存图的几种方式

```text
存图 猫图 [图片]          # 直接发送图片并指定分类
[回复一张图片] 存图 猫图   # 回复图片后发送指令
[回复合并转发] 存图 猫图   # 逐层提取嵌套记录中的图片和视频
存图                       # 按机器人提示完成保存
```

如果关键词没有对应的图库文件夹，插件会根据 `保存失败时的处理方式` 的设置，把文件放入临时目录或取消保存。

合并记录里还有合并记录时，插件会按消息顺序继续向内读取。不需要逐条打开或分别存图；在交互提示后发送合并记录，也使用同样的处理方式。同一记录被多次引用时只保存一次，普通消息中重复出现的图片仍按出现次数保存。

某个内层记录读取失败、超时或达到处理上限时，插件会提示消息未完全读取，并继续保存已找到的媒体。没有找到媒体时，会区分“没有图片或视频”和“记录未能完整读取”。

创建分类和添加别名的指令默认是：

```text
创建关键词 文件夹名 别名1
创建别名 已有关键词 新别名
```

这两条指令不会显示在普通帮助中，并且只有配置在 `允许创建分类的用户` 中的用户可以使用。

## 设置说明

### 图片库与指令

- **图片库目录**：存放分类文件夹的根目录。文件夹名称就是关键词和别名。
- **发图指令名、图库列表指令名、刷新图库指令名**：修改对应指令的名称。
- **创建分类指令名、创建别名指令名**：修改管理用指令的名称。

### 发图功能

- **单次最大发图数量**：一次最多发送多少个文件。发送 `猫图 100` 时，数量会被限制在这里。
- **关键词匹配模式**：
  - `fuzzy` 模糊：消息以关键词开头就会触发，例如 `猫图好可爱` 也可能触发；
  - `exact` 精确：只响应 `猫图` 或 `猫图 3`；
  - `none` 关闭消息触发：只通过 `发图` 指令发图。

### 存图功能

- **临时存储目录**：关键词匹配不到时的备用目录，也是交互式存图使用的目录。
- **上传等待时间**：机器人提示发送图片后，等待回复的时间，单位为秒。
- **保存失败时的处理方式**：开启后，找不到分类会保存到临时目录；关闭后直接取消。
- **最多展开层数**（`forwardMaxDepth`）：默认 32 层，最外层合并记录计为第 1 层，可设置 1–256 层。
- **单次检查节点数**（`forwardMaxNodes`）：默认 10000，包含消息、容器、文本和媒体节点；可设置 1–100000。达到上限后不再继续读取。
- **记录读取等待时间**（`forwardTimeout`）：默认每次 15 秒，可设置 1–120 秒。超时会跳过该记录，继续处理其他内容；这是单次请求的等待时间，不是整个存图任务的总时限。
- **文件名模板**：控制保存后的文件名。可用变量包括：
  - `${userId}`、`${username}`：上传者的 ID 和名称；
  - `${timestamp}`：时间戳；
  - `${date}`、`${time}`：日期和时间；
  - `${index}`：本次保存中的序号；
  - `${ext}`：文件扩展名；
  - `${guildId}`、`${channelId}`：群组和频道 ID。

默认模板是：

```text
${date}-${time}-${index}-${guildId}-${userId}${ext}
```

### 上传权限

上传大小限制按以下顺序生效：具体用户 > 具体群组 > 群组默认值 > 全局默认值。

- `0` 表示禁止上传；
- 用户限制表中的 `default` 是全局默认值；
- 群组限制表中的 `default` 是群组默认值；
- 想让普通用户可以存图，需要把对应限制设置为大于 0 的数值，单位是 MB。

### 调试模式

调试模式只影响控制台日志，不会改变发图和存图行为。遇到匹配或文件类型问题时，可以临时打开它协助排查。

## 文件格式与目录

支持的图片格式：JPEG、PNG、GIF、WebP、BMP、TIFF。

支持的视频格式：MP4、MOV、AVI。

建议目录结构如下：

```text
images/                         # 图片库目录
├── 猫咪-猫图-喵星人/            # 主关键词-别名-别名
│   ├── 1.jpg
│   └── 2.gif
└── 风景-自然/
    └── sunset.mp4

temp/                           # 临时存储目录
```

图库列表会缓存约 5 分钟。新增、删除或重命名文件夹后，使用 `刷新图库` 可以立即生效。

## 适配器说明

普通图片、视频和引用消息使用 Koishi 的消息元素处理，能否完整读取取决于适配器提供的消息内容。

回复消息的 ID 通过标准消息接口读取；合并记录自身的资源 ID 优先通过 OneBot 的 `getForwardMsg` / `get_forward_msg` 读取。支持逐层处理 OneBot 消息段、CQ 字符串和已展开的 `forward`、`message`、`node`、`figure` 容器。

部分 OneBot 实现把合并记录返回为 QQ 聊天记录 JSON 卡片（`com.tencent.multimsg`）。插件也会读取其中的记录 ID，继续提取内层媒体，不把卡片预览中的图片或文字当作完整记录。

其他适配器需要提供已展开的记录内容，或能通过标准消息接口读取对应记录。只有标题、摘要或不可读取的折叠引用时，无法还原内层媒体；插件会在检测到无法展开的合并节点时提示。其他平台私有 JSON/XML 卡片不在当前解析范围内。实际能力仍取决于适配器和记录是否有效。

## 注意事项

1. 图片库目录需要提前创建，并且 Koishi 进程需要有读写权限。
2. 临时存储目录需要有写入权限。
3. 文件夹名称中的 `-` 用来分隔别名；文件夹名和别名尽量不要使用文件系统特殊字符。
4. 定期清理临时目录，避免长期积累文件。
